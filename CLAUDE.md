# Tala

Renamed from Sema on 2026-11-04: the snap name `sema` was taken. The user registered `tala` (Old Norse "to speak"). Older notes below say Sema.

Unofficial snap of the official Nextcloud Talk desktop client (nextcloud/talk-desktop). It repackages Nextcloud's unmodified Linux ZIP. There is no app code here: to change app behavior, contribute upstream.

Status is kept in this file.

## Recipe notes
- Version and ZIP sha256 are pinned in `snap/snapcraft.yaml`.
- The ZIP's top directory is mode 700, so `chmod -R a+rX app` in override-prime is required.
- The client hides its startup setting on Linux. `sema.autostart on|off|status` and the launcher right-click actions provide it.
- No NVIDIA env workaround is needed (tested on RTX 2080, Wayland, gpu-2404).
- Testing: build with `snapcraft pack`, `sudo snap install --dangerous`, then connect browser-sandbox, camera and audio-record by hand. `--remote-debugging-port=9222` exposes GPU and sandbox state over CDP.
- Build on skyfire only with at least 20G free on `/`, then `snapcraft clean`.

## Mention suggestions (built 2026-11-07, released in 0.4.1, the user confirmed mentioning works)
Typing `@` at the start of a word in the composer lists matches from `GET chat/{token}/mentions` (`chatMentions`, `lib/src/mentions.dart`), without the user themselves, at most 5. Arrows move, Enter or Tab or a click picks, Escape closes it for that mention. Searching stops at a space, so people are found by a first word.
The composer shows `@Maya Chen`; `PickedMentions` remembers name to id per conversation (static in `_ConversationPaneState`, so it survives switching conversations like the draft, but not a restart, and nor do drafts) and `expand` sends `@"id"` as `OutgoingMessage.wireText`, while the bubble shows the typed text until the server's copy arrives. A second person with the same name goes in as raw `@"id"`. A name left over in a draft after a restart stays plain text.
`tool/group_check.dart` confirmed on Talk 25.0.7 that picks become real mention parameters, including `all`, and that an unpicked `@nobody` stays text. Federated mentions use `mentionId` per the docs; not run for real.
Logs: `people search failed` used to write the search text to the log through the request path, and `maskReportText` doesn't mask `?search=`. It and mention search now log only the status. ## Markdown (built 2026-11-07, released in 0.4.2, the user confirmed it works)
`lib/src/markdown.dart`: Tala's own small parser, because a package is what the old webapp's fate warns against. Only messages the server flags `markdown: true` are formatted, the same rule as the web client's `useExtendedMarkdown`; system messages come back false and older servers omit it. Handles bold, italic, strikethrough, inline and fenced code, links, headings, quotes, bullet, numbered and task lists, and rules. Tables stay as typed. Images in Markdown aren't drawn.
`ChatMessage.blocks` is the layout, null for anything with nothing to format; `segments` is the flattened text, so previews, quotes and Copy text are clean. `editSource` stays the raw source. A message shows as typed until the server's copy replaces it.
Links only open http and https, through `safeUrl`, and an unsafe one stays as typed. A label can differ from its address, as on the web. `snake_case`, `2 * 3 * 4`, and underscores or asterisks in bare addresses stay untouched; placeholders like `{mention-user1}` are atomic. A delimiter with no closer is remembered so hostile messages don't go quadratic; a test covers them.
Checked: `tool/group_check.dart` on Nextcloud 35.0.2 and Talk 25.0.7. `tool/make_screenshots.dart` loads DejaVu Sans Mono as `monospace`, because tests have no system fonts.

## Report a problem (built 2026-11-06, relay live)

App: `lib/src/report.dart`, `lib/src/report_view.dart`. Relay: `relay/bug-report/` with `worker.test.mjs`; the README lists setup. The Worker is live at `tala-bug-report.jimmy-tigert.workers.dev`, with a token limited to this repo's Issues (read and write). A test POST with curl created issue #5 with the right label and body, and it's closed.
Differences from XBTune: no AI check and no ECM. A `facts` field carries what the app checks: session, tray, snap permissions (`snapctl is-connected`), Nextcloud and Talk versions. The repo is public, so issues are public and the dialog says so. Masking is wider because many log lines quote raw errors: server and other hosts, URLs, room tokens, username, app password, email and IP addresses, home folders (`maskReportText`). Never add names or message text to `log()`: masking can't recognize them. Release stacks have no symbol names, so the fingerprint is the error type plus the message without digits. Network errors are logged but not offered as crashes.
Native crashes: `linux/runner/fatal_signal.cc` appends a line to `fatal.log` and hands on to the previous handler; only the signal's name is known, no stack. `log.txt` now persists across starts, rotating to `log.previous.txt`, so developer modes no longer wipe it.
Checked: 165 tests, relay tests with GitHub faked, SEGV and ABRT on the real build, `--crash-test`, `--report-check` against the real server (read-only, sends nothing), masking on 91 real log lines (nothing needed masking). `snap run tala --report-check` on 0.2.1 (2026-11-06): session, tray, permissions and server all correct. The host OS can't be read: AppArmor denies `/var/lib/snapd/hostfs/usr/lib/os-release` without `system-observe`, which isn't auto-connected, so a `Kernel:` fact from `/proc/version` stands in. XBTune's profile has no such rule either. Not checked: a report sent from the app itself, the dialog on screen, `snapctl` and host OS detection in a real snap (`snap run tala --report-check`).

## Tray and background (built 2026-11-06)
